# BiliNote 分类与 Obsidian 入库方案

状态：可审阅设计草案，尚未改动线上服务。

## 1. 已确认的需求

1. 生成历史增加分类目录，可多选笔记移动到分类，也可取消归类。
2. 归类只修改 BiliNote 内的组织关系，不上传 WebDAV，不调用 Hermes，不发送通知。
3. 手动入库支持单条笔记、多条笔记、整个分类三种范围。
4. 单条与多条入库：Hermes 整理所选笔记，补全标签和关联链接。
5. 整个分类入库：整理全部成员，并综合生成分类归纳页，保留每条来源笔记。
6. 按名称或创建时间排序，支持升序、降序；默认创建时间从新到旧。
7. 清楚记录已归类、未归类，并单独记录未入库、处理中、已入库、待更新、失败。
8. Obsidian 输出包含 Markdown、YAML 属性、标签、双向链接、分类页和总览页。
9. 整理结果校验成功后，通过已有 QQ Bot 通知本人。
10. 修复不同电脑打开同一网站时历史不共享的问题。

## 2. 历史问题的代码结论

核查仓库：1997liuyh-boop/BiliNote，提交 `90940fde4d224d0f69ad99674f4af0a1ea52d3c4`。线上实际版本需要另外核对。

- 前端 `BillNote_frontend/src/store/taskStore/index.ts` 使用 Zustand 和 `idb-keyval`，以 `task-storage` 为键把历史存入当前浏览器的 IndexedDB。
- 历史组件读取上述本地任务列表。轮询代码只查询本地已知任务的状态，无法发现另一台电脑创建的任务。
- 后端 `backend/app/routers/note.py` 把结果保存在 `NOTE_OUTPUT_DIR/<task_id>.json`，提供单任务查询，但当前没有供页面加载的完整历史列表接口。
- 数据库 `video_tasks` 保存视频与任务 ID 的映射，不是含笔记多版本、分类和入库状态的完整历史库。
- 浏览器还保存多个笔记版本，服务器同一个任务的结果文件不能保证还原所有旧版本。

所以，更换电脑、浏览器或网站地址的协议/域名/端口，都可能看到不同的历史列表；这本身不等于服务器笔记已经被删除。是否另有容器数据未持久化的问题，需要查服务器目录和挂载。

## 3. 方案比较

| 方案 | 特点 | 判断 |
| --- | --- | --- |
| BiliNote 统一管理历史和分类，后台任务接入现有 WebDAV、Hermes | 网页内完成全部操作，可跟踪失败与重试，能解决跨电脑历史 | 推荐 |
| 网页只导出文件，由外部目录监听触发 Hermes | 改动较少，但难准确关联整理完成状态、整类范围和网页状态 | 可作过渡方案 |
| 定时扫描所有生成结果自动入库 | 适合全自动收集，但不符合用户明确要求的手动入库 | 不采用 |

沿用现有 React、Tailwind CSS、FastAPI 和 SQLite；本轮不迁移到 Vue，也不引入新的重型队列服务。

## 4. 页面行为

- 生成历史顶部保留搜索，增加排序、批量选择、创建分类。
- 分类目录可展开、收起，并展示成员数量；未归类笔记有独立入口。
- 每条笔记显示所属分类和入库状态，两种状态独立，例如“未归类 / 已入库”。
- 多选后的操作：归入已有分类、新建分类并归入、取消归类、手动入库。
- 分类操作：重命名、整个分类入库、解散分类。解散分类只解除归属，保留原始笔记。
- 点击单条“手动入库”处理该笔记；点击批量“手动入库”只处理勾选的笔记；点击分类“整类入库”处理该分类全部笔记。
- 整类入库必须明确展示范围和数量。分类中存在未完成任务时，提示等待生成结束，不静默跳过后声称整个分类已整理。
- 完成归类后立即刷新已归类/未归类数量，并同步到其他设备。
- 暂按一层分类、每条笔记一个主分类设计，额外主题通过标签表达；不增加复杂嵌套目录操作。

## 5. 服务端历史与迁移

以服务器为统一数据来源，浏览器只缓存展示所需数据。增加分页历史、任务详情、分类和入库状态接口。

- 保存任务 ID、标题、平台、来源、创建时间、完整生成参数、生成状态、分类 ID。
- 单独保存笔记版本，保留生成模型、时间和内容，归档记录指向具体版本。
- 分类保存稳定 ID、名称及创建/更新时间。
- 入库任务保存处理范围、成员版本快照、当前步骤、错误和最终产物路径。
- 历史接口只返回列表摘要，正文按需加载，避免把所有笔记和转写一次传给浏览器。
- 首次迁移先备份，再扫描服务端任务 JSON 建立索引；损坏文件隔离报告，不能阻断其他任务恢复。
- 兼容从旧浏览器导入任务和版本，按任务 ID 与版本 ID/内容摘要去重，不用空数据覆盖完整内容。
- 服务端缺失旧版本时，只有原浏览器还保留的数据或备份能够补回，不能宣称凭空恢复。
- 删除使用任务 ID 和持久化删除标记，避免迁移或缓存合并把已删除记录重新带回。
- 与现有网站访问保护对齐；如果部署有多用户身份，所有查询和迁移按所属用户隔离。

## 6. 手动入库流程

`用户点击入库 → 保存任务及版本快照 → 写入 WebDAV 暂存区 → 通知 Hermes → 整理并生成结果 → 校验及发布到笔记库 → 更新网页状态 → QQ 完成通知`

1. 请求立即返回任务 ID，浏览器可以关闭，后台继续执行。
2. 小型服务器采用持久化任务表与单并发工作进程，重启后可恢复未完成任务。
3. 重复点击同一范围和版本不会创建重复整理任务；重试复用原任务状态。
4. WebDAV 上传清单、源笔记和附件成功后才触发 Hermes，不能读取半份输入。
5. Hermes 的具体连接方式以服务器版本为准：优先复用已支持的鉴权 Webhook；缺少该能力时采用本机适配服务调用已安装 CLI。
6. Hermes 只整理本次任务授权范围，生成来源引用、标签和关系，整类任务额外做综合归纳与差异比较。
7. Hermes 提交结构化结果清单。接收端检查任务身份、输出路径、文件存在、YAML、链接及来源成员完整性。
8. 校验通过才标记已入库并发送 QQ 完成提醒。Webhook 返回“已接收”或 Agent 回答“完成”都不直接算整理成功。
9. 上传、整理、发布、通知分别保存状态。通知失败可单独重试，不重复运行已完成的整理。
10. QQ 使用确定的本人目标会话；以任务 ID 记录发送结果，超时无法确认是否送达时保留“不确定”状态，避免无条件重复发送。

分类新增成员、成员版本变化或分类重命名后，如果与上次入库快照不一致，分类显示“待更新”。重新点击整类入库后更新分类归纳页。

## 7. Obsidian 文件规范

以下是新模块负责维护的子目录示例，最终会放入现有 WebDAV 笔记库的正确位置：

```text
BiliNote/
  总览.md
  分类/
    人工智能--分类短ID.md
  笔记/
    示例笔记--任务短ID.md
  附件/
    任务ID/
```

文件名由标题与稳定 ID 组成，避免同名覆盖。标题清理非法路径字符，实际引用使用完整库内路径。归类先在 BiliNote 内建立目录关系；WebDAV 目录只在手动入库时更新。

示例笔记格式（示例内容，不代表已经生成的真实笔记）：

```markdown
---
id: "bilinote-任务ID"
title: "示例笔记"
aliases:
  - "示例笔记"
tags:
  - bilinote
  - 人工智能/知识管理
category_id: "分类ID"
source: "原始视频链接"
created: "2026-09-13T15:00:00+08:00"
updated: "2026-09-13T15:10:00+08:00"
---

# 示例笔记

所属分类：[[BiliNote/分类/人工智能--分类短ID|人工智能]]

返回：[[BiliNote/总览|笔记总览]]

## 核心内容

由 Hermes 根据来源笔记整理的正文。

## 关联笔记

- [[BiliNote/笔记/相关笔记--另一任务短ID|相关笔记]]：明确说明关联原因。
```

- 原始笔记和归纳页分开保存，归纳结论保留可追溯来源。
- 分类归纳页包含主题概述、共同观点、差异/冲突、建议阅读顺序和全部来源链接。
- 总览页包含分类入口、已入库笔记数量、最近入库条目和未归类但已入库的笔记入口。
- 总览是普通 Markdown，无需 Dataview 插件即可查看。
- 标签用于主题筛选；正文中的 `[[双向链接]]` 形成笔记之间的关系图。只加标签不会自动产生有意义的笔记关系。
- 附件复制到库内并改为库内引用，不保留只有网站可用的相对 `/static/...` 图片地址。
- 模块只维护自己的生成文件；用户手写内容通过保留区段或独立页面保存，更新时检测冲突，不覆盖无关笔记。
- WebDAV 是同步目标，电脑端仍需已有的 Obsidian 同步工具把该目录同步到本地 Vault；需要核对当前工具和实际 Vault 根目录。

## 8. 验收标准

1. 电脑 A 生成，电脑 B 访问同一网站可见；刷新或重启后分类仍存在。
2. 单条、多条归类及取消归类正确更新计数，操作不发出 WebDAV/Hermes/QQ 请求。
3. 名称与时间排序、搜索和分类筛选可以组合使用。
4. 三种手动入库范围准确，整类入库包含全部完成笔记并生成综合归纳页。
5. 重复点击、进程重启、WebDAV 中断、Hermes 超时、通知失败都有可见状态及合理重试。
6. 中文标签、特殊标题、同名笔记、多版本、图片引用均能正确处理。
7. Obsidian 能打开总览、分类页和笔记，内部链接可跳转，关系图有实际连接。
8. QQ 完成提醒只在产物校验成功后发送，包含分类/范围、数量和总览位置。
9. 升级前后笔记数量及版本数可对照，原始数据与现有手写文档保留。
